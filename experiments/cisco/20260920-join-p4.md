## 1. 运行模式

- **每轮独立 DTLS 会话**：Discovery 前奏（同 5 元组，**并消费 Discovery Response**）→ 握手（等飞行闭合 + 1.5s 沉降）→ Join Request → 15s 等待 → 优雅关闭（stdin EOF → close_notify）；
- **retries=1**：非 ANSWERED 时换新会话重试一次（见 §3）；
- 判定：Result Code（Type 33）/ alert（s_client 被服务端关闭）/ silence / btrace disjoin 抽样核对。

## 3. 调试中发现的环境事实（fuzzer 行为依据）

1. **同 5 元组压制**：固定源端口连发时，首轮 rc=0 后第 2–4 轮全静默（会话存活窗口内新握手被压制）；btrace 显示 Join 阶段会话约 **32s** 心跳超时释放；
2. **换端口重试有效**：临时源端口下首次尝试大概率落在上一会话存活窗口内被丢，第二次尝试（新会话≈20s 后）稳定命中——`locked20` 的 19/20 二次命中即此形态；
3. **cfmgr 教训**：P4 bring-up 时误跑含 cfmgr 全零补丁的 `patch.sh` → join 全部 "Failure encoding auth token payload"（E5 已知），改用 `revert_cfmgr2.sh` 还原后恢复正常；patch.sh 的 cfmgr 段在该实例上禁用。

## 5. btrace 抽样核对（`show logging process wncd to-file`）

矩阵窗口 10:11–10:19Z 解码：

- alert 轮（omit-37/29、radio-1base）：`Internal Error, Phase: Join`（10:14:31–10:14:45 三条，与轮次时间窗吻合）；
